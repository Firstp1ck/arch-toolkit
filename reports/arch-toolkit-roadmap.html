Release boundary

Authorization is still required. The repository is packageable as 0.3.0, but this work did not create a commit or tag, push a branch/tag, mutate a GitHub release, or publish to crates.io. Those are external side effects and require a separate explicit request.
  • Allowed and completed: local formatting, linting, tests, docs, package listing, and publish dry-run.
  • Not performed: commit, tag, push, GitHub release creation/update, and crates.io upload.
  • External scope: Pacsea migration and parity verification.

Residual risks and deliberate limits

Synchronous metadata providers

A provider that ignores its supplied timeout can still block its caller. The resolver cannot safely preempt arbitrary synchronous I/O without a new execution contract.

Pkgver segmentation

Conditional pkgrel behavior now matches libalpm. Some unusual separator-level pkgver differences pre-date this work; documentation no longer claims full algorithm parity.

Error categorization

Some task/transport failures remain mapped through ArchToolkitError::Parse. Messages are actionable, but programmatic categorization is deferred.

Static PKGBUILD analysis

The analyzer intentionally does not execute Bash and is not a full shell parser or reputation scanner. Findings are deterministic indicators, not proof of safety.
